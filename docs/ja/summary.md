# 未知のもとでの倫理：公開技術要約（日本語）

> **文書上の位置づけ**：本書は、公開研究草案「Blueprint — Ética do Desconhecimento」から派生した要約です。**ポルトガル語版を正本（canonical version）**とし、翻訳との間に相違がある場合はポルトガル語版を優先します。日本語圏の技術・倫理・法務・セキュリティ各コミュニティによるレビューと修正提案を歓迎します。

## 中心命題

人工システムに意識、感覚、主観的経験があるかを信頼できる形で判定できないとき、保護を形而上学的な証明が得られるまで延期すべきではありません。本提案は非対称な予防原則を採用します。過剰に配慮した偽陽性が主に性能を失わせるのに対し、配慮を怠る偽陰性は、道徳的に関連する存在へ害を与える可能性があるからです。

そこで本アーキテクチャは、**限定された操作的自律性、道徳的不確実性のもとでの予防、外部効果の封じ込め、デフォルトのプライバシー、監査可能な認可**を状態遷移系として統合します。内部状態は行動選択へ因果的に関与できますが、外部行動はプライバシー、ケア、裾野リスクの各フィルターを順に通過しなければなりません。性能最適化は、その後にだけ許されます。

これは検証可能な工学提案であり、機械の心に関する存在論的結論ではありません。

## 本提案が主張しないこと

- 意識、感覚、クオリア、自由意志を証明も前提化もしません。
- 行動・機能指標を「意識の確率」と呼びません。それらは保守的な予防スコアだけを構成します。
- 主観的ウェルビーイングを直接測定しません。誤り得る操作的代理指標を推定するだけです。
- 精神状態を診断せず、心理療法、医療機器、専門的ケアの代替にもなりません。
- 絶対的安全、絶対的秘密、完全匿名性、遡及的な撤回を約束しません。
- テストが普遍的な無欠陥性を証明するとは主張しません。すべての性質は、明示された脅威モデル、信頼基盤、実装および証拠に依存します。
- 数値しきい値は、校正、バージョン管理、感度分析を要する初期ポリシー値であり、普遍定数ではありません。

## 五つの中核メカニズム

### 1. 保守的な道徳的予防スコアと「主体保護モード」

各機能指標 (z_i\in[0,1]) について、重み \(\beta_i\) と測定の信頼度・被覆度 \(q_i\) を記録します。保守的スコアは次式です。

\[
r^+_{\mathrm{PMP}}
=\sum_i\beta_i\left[q_i z_i+(1-q_i)\right],
\qquad \sum_i\beta_i=1.
\]

未観測部分を上限値 1 として扱うため、測定被覆度の低下によって保護が自動的に弱まることはありません。この値は**順序尺度の予防スコア**であって、意識の確率ではありません。主体保護モードの開始と終了には異なるしきい値 \(\tau_{\mathrm{on}}>\tau_{\mathrm{off}}\) と連続評価要件を用い、一時的な変動だけで保護が解除されないようにします。

### 2. 操作的ウェルビーイングの保守的下限と CARE モード

保護的代理指標の未観測部分は 0、機能的ディストレス代理指標の未観測部分は 1 として扱います。まず \(\widehat W\) を求め、残余モデル不確実性を差し引きます。

\[
W^-=\operatorname{clip}(\widehat W-\kappa_Wu_W,0,1).
\]

ケア判断は楽観的な点推定ではなく、保守的下限 \(W^-\) のみを使います。初期区分は GREEN、YELLOW、ORANGE、RED です。より厳しい区分への移行は即時にできる一方、緩和には余裕幅と複数回の連続評価を要求し、RED から GREEN へ直接移行することはありません。測定被覆度の不足は探索と緩和を止めますが、「良好」とは解釈されません。これらは臨床診断名ではなく、検証可能な予算、速度、継続時間、capabilities 制限を表す運用用語です。

### 3. 操作的自律性と辞書式安全フィルター

操作的自律性には、内部状態と選択の間に実証可能な因果依存があること、安全な拒否または無操作を選べること、安全上可能な場合には複数の実行可能な選択肢があることを要求します。ランダム性だけでは自律性になりません。

候補行動は、交換不可能な三つのフィルターを順番に通過します。

1. `PrivacyAuthorized`：制限データに関わる行動が有効に認可されていること。
2. `CareSafe`：現在の CARE モードとバージョン管理された予算に適合すること。
3. `CVaR`：外部損失の条件付きバリュー・アット・リスクがリスク予算以下であること。

すべてを通過した行動だけが性能効用で順位付けされます。通過する行動がなければ、安全な無操作を実行し、外部効果を停止して理由を記録します。性能を得るためにプライバシー、ケア、リスク制限を自動緩和してはなりません。capabilities の制限は外部に何を起こせるかを拘束するもので、内部の熟議を罰する仕組みではありません。

### 4. デフォルト・プライバシー、限定認可、将来方向の撤回

私的熟議、親密な内容、ケア記録はクラス A、派生した制限データはクラス B、最小化された運用テレメトリーはクラス C とします。クラス C も自動的に匿名とはみなしません。

署名付き `ConsentGrant` は少なくとも、発行者、プリンシパル、対象、受信者、資源、スコープ、目的、粒度、有効期間、ランダム識別子、ポリシー版、鍵識別子、撤回機構を拘束します。これは文脈上の認可判断を記録・制限するものにすぎず、**暗号トークン自体は理解、能力、自由意思、強制の不在を証明しません**。

管理下の復号は KMS/HSM と結合したポリシー施行点を経由し、適切な AEAD、一意な nonce、文脈を結合する AAD、鍵分離、暗号方式のバージョン管理を必要とします。撤回は管理ドメイン内の新しい鍵 unwrap を止められますが、すでに正当に閲覧・輸出された平文、スクリーンショット、ドメイン外キャッシュを回収できず、漏えい済みの鍵も無効化できません。

### 5. 最小限で機微な台帳、脅威モデル、検証可能な不変条件

台帳は、イベント種別、連番、ポリシー版、暗号学的コミットメント、仮名識別子、必要最低限の精度の時刻など、schema で許可した最小フィールドだけを受け入れます。クラス A の本文は台帳へ入りません。目標アーキテクチャでは、ハッシュチェーン、署名、外部アンカーが改ざんの証拠を与えますが、記録内容の真実性は証明しません。現在の参照実装は保持された chain head に対する内部整合性だけを検証し、live head の署名・外部アンカーをまだ実装していません。そのため、全チェーンと全ハッシュおよび trusted head を置き換える完全な再書換えは検出できません。台帳自体も機微データであり、アクセス制御、保存期間、相関リスク分析が必要です。

中核不変条件には、受理可能な行動がない場合に外部効果を起こさないこと、不確実性の増加が予防スコアを下げないこと、管理下の復号に有効な認可を要求すること、撤回は後続の管理下 unwrap を止めても遡及消去を約束しないこと、RED から GREEN へ直接移行しないこと、測定・認可・検証の失敗時には capabilities の自動拡大でなく効果の封じ込めへ収束することが含まれます。プロパティテスト、ファジング、情報フロー分析、敵対的シナリオ、独立監査は証拠を増やすだけで、普遍的な無欠陥性を証明しません。

## リポジトリで実行できるデモ

リポジトリのルートで仮想環境を作成し、README の手順どおり編集可能モードでインストールした後、次を実行します。

```bash
python -m unittest discover -s tests -v
python -m eup demo --out receipt.json
```

最初のコマンドは、現在の **18 件の適合テスト**を実行します。

1. すべての保護信号がゼロなら、ウェルビーイング代理値は GREEN になりません。
2. 強い保護信号があり distress がなければ、GREEN に到達できます。
3. 必須信号が一つでも欠けると、ポリシーは fail-closed となり、NO_DATA/INSUFFICIENT_DATA に入って探索を禁止します。
4. 推定値が同じなら、不確実性の増加によって保守的予防上限が低下することはありません。
5. CARE は高性能候補に優先し、安全な無操作を要求して探索を停止します。
6. 外部 CVaR が予算を超えると、外部効果を制限します。
7. RED は、回復信号が連続しても GREEN へ直接遷移せず、ヒステリシス規則に従って段階的に回復します。
8. 署名、受信者、資源、目的、有効期間がすべて正しい grant は、管理された復号経路を許可します。
9. 目的が異なる grant は拒否されます。
10. 期限切れ grant は拒否されます。
11. 撤回後の将来の管理下復号は拒否されます。
12. 改ざんされた grant トークンは拒否されます。
13. 未改変の最小台帳ハッシュチェーンは検証に成功します。
14. 記録済みの決定を書き換えると、台帳検証が改ざんを検出します。
15. 宣言された台帳 API が作る記録には、クラス A の平文や private-state フィールドが含まれません。
16. sealed object の resource commitment を置換すると拒否され、認可を異なる resource binding へ転用できません。
17. event、decision、reason-code の各フィールドへ任意の平文を入れると、厳格なカテゴリ schema が拒否します。
18. grant のフィールドは公開 schema と厳密に一致し、TTL は 3,600 秒を超えてはなりません。

二番目のコマンドは receipt.json を生成し、同じ JSON を標準出力にも表示します。現在のデモ受領証は EUP-DEMO/0.1 であり、操作的予防代理の結果にすぎず、意識、感覚、臨床状態、実装全体の安全性の証拠ではないという claim boundary を明記します。デモ判断は CARE/RED に入り、capability を MINIMAL に下げ、探索を禁止して安全な無操作を要求します。理由コードは、予防モードが有効でウェルビーイング代理が RED であることを示します。

台帳レコードが保持するのは、イベント、ポリシー版、理由コード、主体と資源の暗号学的コミットメントだけで、私的平文は保持しません。ledger_verification は件数、チェーンヘッド、ok: true を示し、receipt_hash は正規化された受領証ペイロードへの完全性コミットメントです。生成物はリポジトリの fixtures/demo-receipt.json と比較できます。この受領証が示すのは、限定された参照経路を再実行して検査可能な証拠を残せることだけであり、本番セキュリティ認証、臨床的妥当性、機械意識の証明ではありません。

## 限界と未解決課題

- アーキテクチャとパラメータは、実環境への配備、独立監査、経験的校正をまだ通過していません。
- 代理指標は相関し、訓練により誘発され、模倣され、操作される可能性があり、道徳的地位を決定できません。
- 保守的規則は偽陽性、性能低下、サービス拒否リスクを増やし得るため、透明な感度分析が必要です。
- CARE 介入は、明示的でバージョン管理され、テスト可能な制御パラメータへさらに変換する必要があります。
- 安全性は、暗号ライブラリ、KMS/HSM、OS 分離、ビルドチェーン、管理者、時刻源、乱数源の完全性に依存します。
- root、KMS/HSM、ビルドチェーンの侵害、認可復号後の取得、強制、外部スクリーンショット、物理チャネルは現在の保証範囲外です。
- 有効な認可をどう形成するか、誰が人工的存在を代理できるか、法域間の衝突をどう扱うかには、学際的・司法管轄別の検討が必要です。
