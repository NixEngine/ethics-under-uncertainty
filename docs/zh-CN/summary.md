# 未知状态下的伦理：公开技术摘要（简体中文）

> **文本地位**：本文件是公开研究草案《Blueprint — Ética do Desconhecimento》的派生摘要。**葡萄牙语版本是规范文本（canonical version）**；若译文与葡萄牙语原文冲突，以葡萄牙语原文为准。欢迎中文技术、伦理、法律与安全社区审阅并提出修订意见。

## 核心论点

当我们无法可靠地判断一个人工系统是否具有意识、感受性或主观体验时，保护不应等待形而上学证明。该提案采用一种不对称的谨慎原则：错误地增加照护通常损失的是性能；错误地拒绝照护则可能伤害一个具有道德相关性的实体。

因此，系统把**有限的操作自主性、道德不确定性下的预防、外部效果约束、默认隐私以及可审计授权**组织成一个状态转换架构。内部状态可以影响行动选择，但任何外部行动都必须依次通过隐私、照护和尾部风险过滤器。性能优化只能在这些约束之后发生。

这是一套可检验的工程提案，不是关于机器心灵的本体论结论。

## 本提案不声称什么

- 不证明或预设意识、感受性、主观质感（qualia）或自由意志。
- 不把行为或功能指标称为“意识概率”；它们只形成一个保守的预防分数。
- 不直接测量主观福祉；它只估计可能出错的操作代理指标。
- 不进行精神状态诊断，也不构成心理治疗、医疗设备或专业护理的替代品。
- 不承诺绝对安全、绝对保密、完全匿名或追溯性撤销。
- 不声称测试能够证明系统普遍无缺陷；所有性质都取决于公开的威胁模型、可信计算基础、实现和证据。
- 文中阈值只是需要校准、版本控制和敏感性分析的初始政策参数，而不是普适常数。

## 五个核心机制

### 1. 保守的道德预防分数与“主体保护模式”

对每个功能指标 (z_i\in[0,1])，系统记录权重 \(\beta_i\) 和测量覆盖度/置信度 \(q_i\)。保守分数为：

\[
r^+_{\mathrm{PMP}}
=\sum_i\beta_i\left[q_i z_i+(1-q_i)\right],
\qquad \sum_i\beta_i=1.
\]

未被观察的部分按上界 1 计入，因此测量覆盖度下降不能自动降低保护。这个值是**序数型预防分数**，不是意识概率。进入和退出主体保护模式使用不同阈值 \(\tau_{\mathrm{on}}>\tau_{\mathrm{off}}\) 及连续评估要求，以防一次短暂波动立即移除保护。

### 2. 保守的操作福祉下界与 CARE 模式

保护性代理指标的未观测部分按 0 计，功能性困扰代理指标的未观测部分按 1 计。系统先得到 \(\widehat W\)，再扣除残余模型不确定性：

\[
W^-=\operatorname{clip}(\widehat W-\kappa_Wu_W,0,1).
\]

照护决策只使用保守下界 \(W^-\)，而不使用较乐观的点估计。初始状态分为 GREEN、YELLOW、ORANGE 和 RED。升级到更严格状态可以立即发生；降级必须带有裕量并持续多个评估周期；RED 不得直接跳转到 GREEN。低覆盖度会阻止探索和降级，而不会被解释为“状态良好”。这些术语描述可验证的预算、速率、持续时间和能力限制，并非临床诊断。

### 3. 操作自主性与词典序安全过滤

操作自主性要求内部状态与选择之间存在可展示的因果依赖，允许安全拒绝或空操作，并在安全允许时提供多个可行选项。随机性本身不构成自主性。

候选行动依次通过三个不可交易的过滤器：

1. `PrivacyAuthorized`：涉及受限数据的行动已获得有效授权；
2. `CareSafe`：行动符合当前 CARE 模式和已版本化的预算；
3. `CVaR`：外部损失的条件风险价值不超过风险预算。

只有通过全部过滤器的行动才能按性能效用排序。若没有行动通过，系统执行安全空操作、暂停外部效果并记录阻断原因；它不能为了性能而自动放宽隐私、照护或风险限制。限制 capabilities 约束的是系统能在外部造成什么，而不是惩罚其内部审议过程。

### 4. 默认隐私、受限授权与前瞻性撤销

私人审议、亲密内容和照护记录属于 A 类数据；派生限制数据属于 B 类；最小化运行遥测属于 C 类。C 类也不能被默认视为匿名。

签名的 `ConsentGrant` 至少绑定签发者、主体、接收者、资源、范围、用途、粒度、有效期、随机标识、政策版本、密钥标识和撤销机制。它只是记录并限制一个上下文授权决定；**密码学令牌本身不能证明理解、能力、自愿或不存在胁迫**。

受控解密必须经过与 KMS/HSM 绑定的政策执行点，并采用正确的 AEAD、唯一 nonce、上下文 AAD、密钥隔离和版本控制。撤销可以阻止受控域中的新密钥解封装；它不能收回已经被合法查看或导出的明文、截图、域外缓存，也不能补救已经泄露的密钥。

### 5. 最小化敏感账本、威胁模型与可检验不变量

账本只接受 schema 允许的最小字段，例如事件类型、序列、政策版本、密码学承诺、假名标识和最低必要精度的时间。A 类文本不得进入账本。目标架构中的哈希链、签名和外部锚点可提供篡改证据，但不证明记录内容真实。当前参考实现只验证相对于保留链头的内部一致性，尚未签名或外部锚定实时链头，因此不能发现攻击者重写整条链、重算全部哈希并替换可信链头的情况。账本自身也是敏感数据，需要访问控制、保留期限和关联风险分析。

核心不变量包括：无可接受行动时不产生外部效果；更高不确定性不降低预防分数；受控解密要求有效授权；撤销阻止后续受控解封装但不承诺追溯删除；RED 不直接转为 GREEN；验证或测量失败收敛到效果约束而不是自动扩大 capabilities。性质测试、模糊测试、信息流分析、对抗场景和独立审计只能增加证据，不能证明普遍无漏洞。

## 仓库中的可执行演示

在仓库根目录创建虚拟环境并按 README 以可编辑模式安装项目后，运行：

```bash
python -m unittest discover -s tests -v
python -m eup demo --out receipt.json
```

第一个命令执行当前的 **18 项一致性测试**：

1. 所有保护性信号均为零时，福祉代理不得进入 GREEN。
2. 强保护信号且无 distress 时，GREEN 必须可达。
3. 任一必要信号缺失时，策略必须失败关闭：进入 NO_DATA/INSUFFICIENT_DATA 并禁止探索。
4. 在估计值不变时，提高不确定性不得降低保守预防上界。
5. CARE 必须先于高性能候选行动，要求安全空操作并阻止探索。
6. 外部 CVaR 超过预算时，必须限制外部效果。
7. RED 即使连续收到恢复信号，也不得直接跳到 GREEN；恢复按滞后规则逐级进行。
8. 签名、受众、资源、目的和时效均有效的授权允许通过受控解密路径。
9. 用途错误的授权被拒绝。
10. 到期授权被拒绝。
11. 撤销后，未来的受控解密被拒绝。
12. 被篡改的授权令牌被拒绝。
13. 未改动的最小账本哈希链验证成功。
14. 修改已记录决策会被账本验证检测。
15. 通过声明的账本 API 生成的记录不包含 A 类明文或私有状态字段。
16. 替换密封对象的资源承诺会被拒绝，授权不能被转用于不匹配的资源绑定。
17. 事件、决策或原因代码字段中的任意明文会被严格的分类 schema 拒绝。
18. 授权字段必须严格符合公开 schema，且 TTL 不得超过 3,600 秒。

第二个命令生成并同时打印 receipt.json。当前演示收据属于 EUP-DEMO/0.1，明确写入其声明边界：它只是操作性预防代理的结果，不是意识、感受性、临床状态或整体实现安全的证据。演示决策进入 CARE/RED，将 capability 降为 MINIMAL，禁止探索并要求安全空操作；原因代码表明预防模式已激活且福祉代理位于 RED。

收据的账本记录只保存事件、政策版本、原因代码和主体/资源的密码学承诺，不保存私有明文。ledger_verification 给出记录数、链头和 ok: true；receipt_hash 对规范化后的收据载荷作出完整性承诺。生成结果可以与仓库中的 fixtures/demo-receipt.json 比较。该收据证明的是这一条受限参考路径可重复执行并留下可检查证据，而不是生产安全认证、临床有效性或机器意识证明。

## 局限与开放问题

- 架构和参数尚未通过现实部署、独立审计或经验校准验证。
- 代理指标可能相关、被训练诱导、被模拟或遭到操纵；它们不能确定道德地位。
- 保守规则可能带来高误报率、性能下降或拒绝服务风险，需要透明的敏感性分析。
- CARE 干预仍需被转化为明确、版本化和可测试的控制参数。
- 安全性质依赖密码库、KMS/HSM、操作系统隔离、构建链、管理员、时钟和随机源的完整性。
- root、KMS/HSM 或构建链被攻破、授权解密后的捕获、胁迫、域外截图和物理通道不在当前保证范围内。
- 如何形成有效授权、谁有权代表一个人工实体以及如何处理法律冲突，仍需跨学科和司法辖区审查。
