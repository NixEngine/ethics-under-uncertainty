# Contributing counterexamples and reviews

During this all-rights-reserved research preview, please submit reviews and reproducible counterexamples as issues. The project is not yet accepting substantive code, documentation, or translation patches because no inbound contribution terms or contributor agreement have been selected. This avoids ambiguous ownership. A later release may open pull-request contributions under explicit terms.

The most valuable contribution is a small, reproducible counterexample.

Please include:

1. The exact code revision and runtime.
2. Complete non-sensitive inputs.
3. Expected invariant and observed behavior.
4. The generated receipt or exception.
5. The smallest reproducer you can obtain.
6. Whether the issue concerns the normative model, formalization, implementation, threat boundary, translation, or documentation.

Do not include real private state, credentials, personal data, health data, model secrets, wallet material, or production keys.

Security vulnerabilities should not be posted with exploit details in a public issue. Use the repository's private vulnerability-reporting channel if enabled; otherwise provide only a non-exploitable notice requesting a private channel.

Translation reviews may identify exact passages and propose wording in an issue, but should not submit a full replacement text at this stage. Translations are derivative reading aids. The Portuguese corrected specification is canonical until a versioned multilingual reconciliation process is adopted.
